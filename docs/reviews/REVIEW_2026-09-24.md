## 1. Confirmed bugs

### Data pipeline (`collect_data.py`, `cache.py`, `wcl_client.py`)

1. `[BUG]` **`_include` beats `_ignore`; the warning says the opposite.** `_select_reports` removes ignored codes from `out`
   (`collect_data.py:1187`), so they are no longer in `have`, so `:1192` re-adds any code that is in both lists. `build_dashboard.py`
   warns "(ignore wins)". Fix (S): `extra = [c for c in includes if clean_code(c) not in have and clean_code(c) not in ignored_codes]`.
2. `[BUG]` **Two loggers on one night double-count.** Pulls are keyed by report + fight, never de-duplicated (`:1301-1319`), and
   `busy_ms_between` (`:240-247`) sums overlapping intervals instead of unioning them, so two logs of the same night double pulls,
   idle time and pulls/hour. (CLAUDE.md records that 2026-08-31 had two loggers covering different halves; the code has no guard
   for the overlapping case.) Fix (M): merge sorted intervals; drop a pull whose `(encounter_id, difficulty, absolute_start_ms ±5 s)`
   already exists, keeping the longer report.
3. `[BUG]` **Logs started after midnight are skipped or split.** `classify_night` (`:297-322`) uses the report's own start weekday: a
   Thursday raid whose log begins Fri 00:10 classifies as `None` and is dropped; a second log started after midnight gets a different
   `night` label. Fix (S): shift by a raid-day rollover (`RAID_DAY_START_HOUR`, default 06:00) before weekday/date lookups and labels.
4. `[BUG]` **The "WCL API calls this run" summary undercounts.** `cache.stats` is reset (`:1235`) after `_select_reports` (`:1232`)
   already made calls, and `fetch_guild_reports` never calls `count_api_call`. Fix (S).
5. `[RISK]` **Bundle fallback misfires and does not persist.** `_fetch_bundle_batch` (`:645-657`) treats any `WCLError` (timeout after
   4 attempts, "report too large") as "WCL rejected the extras" and degrades the whole run to `min` bundles; next run the flag is
   `True` again and the `min` cache key is never consulted, so those bundles are re-downloaded every run. Fix (S): fall back only when
   the message names an unknown field; look up the `min` key when `full` is missing.
6. `[RISK]` **HTTP errors bypass the retry loop.** `wcl_client.py:114` `raise_for_status()` raises `requests.HTTPError`; the loop at
   `:116` catches only `ConnectionError`/`Timeout`, and callers catch `WCLError`, so a transient 5xx aborts with a traceback. Fix (S):
   catch `requests.RequestException`, wrap in `WCLError`.
7. `[RISK]` **Partial GraphQL responses are discarded and one bad fight aborts the build.** Any `errors` entry raises even when `data`
   holds the other aliases; `pool.map` propagates; `collect` dies. Fix (M): return `(data, errors)`, keep non-null aliases, isolate
   per-report failures and exit non-zero at the end.
8. `[RISK]` **`report: null` is cached until the endTime changes** (`cache.py` writes any response; `get_report` accepts `None`). Fix (S):
   do not cache a null report.
9. `[RISK]` **Date range is UTC, nights are local** (`fetch_reports.py`, `collect_data.py:1198`): for Europe/Amsterdam the inclusive
   range runs 02:00 to 02:00. Fix (S): build the bounds with `get_timezone()`.
10. `[RISK]` **Corrupt cache file aborts the build**; `save_meta` writes in place, unlike `_write`. Fix (S): delete-and-refetch on
    `ValueError`; write meta through `_write`.
11. `[RISK]` **Players without combatant info render as unprepared**: `:1366-1368` creates `{prepot: False}` for every participant, so
    the Preparation table shows flask/food missing. Latent (0 of 681 cached bundles). Fix (S).
12. `[RISK]` **Empty realm splits a character** (`Labeller.learn` records `""` as a realm; rankings' `server` can be null). None in the
    current cache. Fix (S): ignore empty servers in `learn`.

### Dashboard (`dash/`, `dash/static/dash.js`)

13. `[BUG]` **Sorting a deaths table pulls nested recap rows into the outer table.** `wireSort` uses descendant selectors
    (`table.sortable th`, `tbody.querySelectorAll('tr')`); the first-death, single-pull and player-focus tables embed
    `<table class='recap'>` inside a `<td>` (`recapHtml`, `dash.js:206-214`). Sorting moves the recap `<tr>`s into the outer tbody as
    4-cell rows. Fix (S): `:scope > thead > tr > th` and `Array.from(tbody.children)`. **The redesign plan's Task 3 rewrites `wireSort`;
    fold this fix in there.**
14. `[BUG]` **Phase filter and phase counts are wrong on cyclic bosses.** `_phase_counts` (`payload.py:80-92`) stores one count per
    timeline *segment*; `hitsOf` (`dash.js:383`) indexes with the position in the de-duplicated `phaseOrder`. Verified in the built
    payload: Entombed Sentinels (N+H, all pulls), The Lost Explorers (N+H), Sszorak (N+H) have timelines where a phase name repeats.
    "Hits in: Stage One" shows only the first Stage One segment. Fix (S): sum `row[5][j]` over every `j` where `p.pt[j][0]` is the
    chosen phase.
15. `[BUG]` **"First death, in which phase" denominators count segments, not pulls** (`dash.js:357`): Sszorak Heroic reports a phase
    reached 61 times over 40 pulls. Same defect in `home.insights` (`home.py:145-149`, `reached` built from `phase_timeline[1:]`),
    latent because the current prog boss is not cyclic. Fix (S): count distinct phase names per pull.
16. `[BUG]` **Tab tooltip with only the Nights-type filter reads " was not in any pull on this boss"** (`dash.js:678`, empty
    `G.player` branch). Fix (S): add a `G.ntype` branch.
17. `[RISK]` **`median` is the upper median for even counts** (`common.py:56-58`, `dash.js:30`): median of two pulls is the larger.
    Affects time to first death, time-to-phase, `_night_score`, box ranking. Fix (S): average the middle pair in both.
18. `[RISK]` **Start-up is all-or-nothing**: `await Promise.all(inflate…)` runs before tabs, sorting, toggles and deep links are wired.
    One bad payload leaves every tab dead; the UI is inert while 5 MB of JSON parses; the deep-link hash is handled late. Fix (M): wire
    chrome first, `Promise.allSettled` per tab with a per-tab error, inflate a boss on first open.
19. `[RISK]` **Nights-type filter is stored as a pull selection**, so a boss whose pulls are all main shows a gold "filtered" panel
    titled "N pulls selected" though nothing is narrowed (`applyGlobal`, `renderSelection` title logic). Fix (S): track type as a
    filter, not a selection.
20. `[RISK]` `clearAll` / "show everything" / Esc never reset `st.phase`; the phase filter survives "everything". Fix (S).
21. `[RISK]` Heatmap takes avoidable abilities from the top 15 by hits; an avoidable ability outside the top 15 disappears. Fix (S).
22. `[RISK]` Home "no defensive cast" ignores externals (`home.py:160`); the boss tab's `hadDef` counts them. Same number today
    (44/49) but the definitions differ. Fix (S): one helper, one label.
23. `[RISK]` `parse_table` (`raid.py:146`) fixes the metric at the first kill, so a flex player averages DPS and HPS percentiles. Fix
    (S): key by (player, role).
24. `[RISK]` Preparation insight (`home.py:207`) divides by `2 * len(prepared)` even when only one of flask/food is tracked. Fix (S).
25. `[RISK]` Night type inferred from the label suffix `" open"` in three places although pulls carry `night_type` and the payload
    carries `o`. Fix (S): `data-type` on the `<option>`s.

### Mythic+ (`mplus.py`, `dash/mplus_tab.py`)

26. `[BUG]` **Weeks before the first snapshot render as red "0/4 no runs" instead of "?".** `first_seen` (`mplus_tab.py:29`) is the
    earliest run date in the history, not the first snapshot; Raider.IO only serves current + previous week, so the two weeks before
    `roster.txt` existed (13 and 30 runs seen vs 146-156 for full weeks) show false failures and drag down "Weeks met". Fix (S): store
    `first_snapshot` in the history; weeks earlier than `week_start(first_snapshot) - 7 d` are untracked.
27. `[BUG]` **One network error aborts the Raider.IO refresh and discards every player already fetched.** `fetch_profile`
    (`mplus.py:213-226`) has no `try` around `requests.get`; `update_history` writes only at the end. Fix (S): catch
    `requests.RequestException`, print, return `None`.
28. `[BUG]` **A third 429 is silent** (`fetch_profile` falls out of the loop to `return None` with no console line). Fix (S).
29. `[RISK]` A wholly failed refresh (24 × 5xx) still writes the file and bumps `updated`, so it looks fresh for 12 h. Fix (S): skip
    the write when zero profiles succeeded.
30. `[RISK]` `reset_rule()` (`mplus.py:73-76`) does `int(os.getenv(...))` without the guard `requirement()` has; `RESET_WEEKDAY=wed`
    crashes the CLI and silently kills the Home callout. Fix (S): reuse `_int`.
31. `[RISK]` The `week` of a run is frozen at first sight, so changing `RESET_WEEKDAY`/`RESET_HOUR_UTC` later splits weeks
    inconsistently; the EU default hour should be checked once against Raider.IO's displayed reset. Fix (S): `--reweek` option.
32. `[RISK]` Each Raider.IO field returns at most ~10 runs, so a player doing more than 10 keys a week is undercounted in "Runs (8w)".

## 2. Operations (`systemd/`, `post_discord.py`, `build_dashboard.py`)

- `[RISK]` **Exit codes lie.** "No matching boss pulls" returns 0 (`build_dashboard.py:137-139`); the timer script then posts a file
  that does not exist and dies with a traceback in `post_discord.py`. Nothing stops posting an unchanged dashboard on a cancelled
  night. Fix (S): `sys.exit(2)` on no pulls; skip posting when no new fights were fetched.
- `[RISK]` **The timer races the live log.** `OnCalendar=Thu,Sun,Mon 23:45` fires while the uploader may still be running;
  `Persistent=true` replays on boot on arbitrary days; no `After=network-online.target`; the user timer only fires while a session
  exists (`loginctl enable-linger`). Fix (S): `Fri,Mon,Tue 00:45`, require the newest report's endTime to be > 30 min old, add
  `After=`/`Wants=network-online.target`, `StandardOutput=append:` a log file, one `EnvironmentFile` for `WCL_RANGE_START` (now
  duplicated in `.service` and `.sh`).
- `[RISK]` No retry anywhere in the oneshot: one failing report or a webhook 429 ends the run for three days. Fix (S): 3-attempt loop
  in the script; retry the webhook on 429/5xx.
- `[RISK]` `post_discord.py` checks 10 MB only at post time. Fix (S): warn at 8 MB in the build.
- `[DX]` `print` everywhere, no levels or timestamps (open since Review 2). `date +%F` in the script uses the system zone, not
  `RAID_TIMEZONE`. Each run leaves another `dashboard_<start>_to_<today>.html` in the root (three already). Config typos crash at
  import (`int(os.getenv("WCL_MAX_ATTEMPTS"))`). No offline mode: the guild list is never cached, so a warm rebuild without network
  dies after a minute of retries.

## 3. Performance

- `[PERF]` **`.cache/` is 962 MB**: 505 MB damage-taken event pages, 417 MB bundles; 1,105 stale files (75 MB) from superseded
  queries are never pruned. The collector reads ~11 event keys and ~7 table keys (`make_fixtures.slim` already knows the projection).
  Fix (M): store the slimmed projection or gzip cache files (~10×); add `--prune-cache`.
- `[PERF]` Consumable cache key hashes every report ability id: one new potion-like ability in a live report refetches `cons` for every
  fight. Fix (S): key per fight, store the id list inside the entry.
- `[PERF]` Four sequential report-level queries per report could be one aliased query; pass 1 is sequential though independent;
  rankings are one call per kill and could ride in the bundle. ~50 calls saved per month.
- `[PERF]` **Browser**: every pull click re-renders the whole tab and synchronously draws ~13 Plotly plots; old plots are never
  `Plotly.purge`d (each registered a window resize listener); all 16 payloads inflate up front (5.1 MB JSON) though badges need only
  `i, n, k, p, o, parts`; `deaths` is 44 % of Ula'tek's payload (1,035 deaths × 8 recap rows, only first-death recaps appear outside
  single-pull views). Fixes (M): per-boss index in `tab_names` + inflate on first open; `IntersectionObserver` draws; purge before
  `innerHTML`; cap non-first recaps at 3 rows.

## 4. Accessibility and UX (beyond the redesign plan)

- `[A11Y]` `#detail_tabN` is `aria-live='polite'` and receives thousands of nodes per click: screen readers read the whole tab. Use a
  one-line status region.
- `[A11Y]` Charts are `role='img'` with no name (the redesign's `chart()` wrapper adds `aria-label`; histogram/heatmap/box charts still
  need a `<details>` data table).
- `[A11Y]` Global Esc also fires when closing a `<select>` or `<details>`, wiping filters. Ignore when `activeElement` is a form control.
- `[A11Y]` `pct_color` at ≥ 50 % HP renders ~3.7-4.0:1 on the panel. Keep the colour on the border, or clamp lightness.
- `[A11Y]` Keyboard multi-select works only by accident (Ctrl/Shift+Enter); Shift should range-select as on WCL.
- `[UX]` `#oldBrowser` sits after `</main>`; deep links go stale on arrow keys / mobile select / gotab (`replaceState` only on button
  clicks); numeric columns sort ascending first; "Last night was X % idle" should carry the date when read days later in Discord;
  "per week" on the kill-time chart is per night; hidden-player thresholds differ between Players tab, attendance and boss tabs.
