# 05 — Insight catalogue and competitive landscape (per-player analysis for DPS / healers / tanks)

Research date: 2026-09-25. Read-only research; nothing in the repo was modified.

**Method and limits.** `CLAUDE.md` §1/§5/§7 were read for what already exists (pull grid, deaths with recap + defensives before the *first* death, damage taken with `avoidable.json`, Preparation = flask/food/rune/pre-pot + potion/healthstone use, interrupts/dispels, `rankPercent` parses for kills, active DPS, median/best per player). Web sources were fetched directly where possible. Three source families could **not** be read and are cited only through secondary pages or search snippets: (a) every help/article page on `warcraftlogs.com/help/*` and `archon.gg/*/articles/*` sits behind a "Human Verification" gate (confirmed by direct fetch); (b) the WCL v2 GraphQL doc pages (`v2-api-docs/warcraft/*.doc.html`) return 404 — the schema is only browsable through the authenticated GraphQL endpoint; (c) `wipefest.gg` is a JS single-page app; its rendered landing page and its Patreon tiers were read, the per-boss insight pages were not. WoWAnalyzer was read from its `master` source tree on GitHub, which is the most reliable source for its thresholds. Community rules of thumb are marked **[community]**.

## 1. Landscape

### Warcraft Logs (WCL) — the report views
- **Analyze (the standard report tabs)**. Summary (composition, damage/healing done, damage taken by ability, deaths, gear); Damage Done with parse %, item level and **activity** ("the percent of the time that the player is using abilities", hover shows "DPS while active"); Healing with overheal ("Generally seeing overheal amounts around 20-40% is expected"); Damage Taken with a mitigation column ("actual total tankiness" incl. absorbed/blocked); Deaths (order, killing blow, last hits, healing received); Buffs/Debuffs (cooldowns, potions, raid buffs; "Cast By Friendly" mode); Casts; Timeline; Replay; **Compare** (head-to-head overlay of two raiders/logs); Events. Source: https://www.warcrafttavern.com/wow-classic/guides/how-to-use-warcraft-logs/ . Generic (not per spec); free, Premium ≈ $2/month per https://wowcoach.gg/blog/warcraftlogs-vs-wowanalyzer-vs-wowcoach .
- **Problems tab**. A per-boss, hand-coded checklist of raid-wide problems on a pull (expandable sections such as burst-potion and health-potion use; a name appearing there = "something they can work on during the next pull") — https://caesarsfinest.enjin.com/mobile/forum/viewthread/m/10600492/id/19034966-warcraft-logs-log-analysis . It is built encounter by encounter: Kihra stated it takes "approximately 15-20 hours of coding per boss" and unsupported bosses show "Fight Analysis for this boss is still under construction" — https://www.mmo-champion.com/threads/1725785-Warcraftlogs-Problems-analysis-not-working ; in ToS only the first 3 bosses were covered — https://forums.combatlogforums.com/t/problems-tab-for-tos/3698 . Community reports that potion display in Problems stopped working and to use Buffs instead — https://www.mmo-champion.com/threads/2110536-Checking-flasks-and-food-etc . Lesson: a per-boss curated checklist is the highest-value but highest-maintenance part of WCL; a data-driven fallback (Buffs/Casts) is what people actually use.
- **Summary pins**. WCL's own generic fallback: pins that "quickly view totals on hits from avoidable abilities, potion use, healthstone use, dispels, interrupts, etc." — https://classic.warcraftlogs.com/help/pins (page gated; wording from the search snippet).
- **Rankings / parses**. Percentile of same spec, same boss, same difficulty; colours grey <25, green 25-49, blue 50-74, purple 75-94, orange 95-98, pink 99, gold 100 — https://wowcoach.gg/blog/what-your-wow-parse-score-means . "Overall" vs **item-level bracket** percentile (brackets ≈ 3 ilvls wide; bracket percentile "ranks you against everyone that's done the fight that has roughly the same item level as you") — https://raid.flamewreath.com/aboutlogs.html . Eight possible numbers per parse: (ranking vs parse) × (historical vs today) × (all brackets vs bracket) — https://www.archon.gg/classic-vanilla/articles/help/rankings-and-parses (gated; from snippet). Only kills are ranked (the project already relies on this).
- **Composition / Talents**. Summary shows gear, ilvl and talents per player; **Top 100 Talent Heat Maps** per spec/boss and full talent trees with Export (talent import string) / Edit (Wowhead calculator) — https://www.wowhead.com/news/new-warcraft-logs-features-top-100-talent-heat-maps-full-talent-trees-331478 .
- **Multiple Report Analysis** (the paid feature this project reproduces) — https://www.wowhead.com/news/new-feature-on-warcraft-logs-multiple-report-analysis-327996 .
- **Mythic+ "Insights"**. Could not be verified from any public page (WCL help is gated; no announcement indexed). The closest documented analogue is **Keystone Heroes** (reads WCL M+ logs; per-run map of pulls, Events chart with a "Next Cast" column that "automatically calculate[s] if you could have gotten extra uses in", affix-impact section with avoidable damage from Volcanic etc.) — https://raider.io/news/329-keystone-heroes-the-newest-way-to-improve-your-mythic-plus-gameplay . Treat the WCL M+ Insights tab as "reported by the task owner, not independently verified".

### Wipefest (closest analogue to a guild dashboard)
- **What it is.** "Wipefest uses data from Warcraft Logs to display insights and timelines for raid encounters. Insights aim to answer common mechanical questions about every pull, while the timeline aims to give a concise high-level overview of what is happening in a fight." — https://www.wipefest.gg/ (rendered). Supported bosses include the current tier (Nymrissa Wavecaller … Ula'tek) — same page. Discord bot replies to WCL links with the matching Wipefest page — https://www.wipefest.gg/discord?gameVersion=warcraft-live . Legacy code is AGPL, with per-encounter JSON event configs (`Wipefest.EventConfigs`) — https://github.com/gngrninja/Wipefest .
- **Insight catalogue (as concrete as public pages allow).** Wipefest "automatically collates various information on **avoidable damage, debuff durations, dispel timings, enemy healing, tank swaps, soaks, and interrupts**" and pulls in Mythic Trap tips/videos; it offers "player scores, event timelines, guides, and multi-pull analysis" — https://www.archon.gg/classic-mop/articles/news/wipefest-siege-of-orgrimmar (gated; snippet). Named insights from the Archon/WCL articles: **Ready check** (consumables, enchants, gear, world buffs), **combat and mana potions**, **healing potions, healthstones and bandages**, **Deaths & avoidable damage**, **Soaks** ("which players were in or not in each individual soak"), **Interrupts** ("who is interrupting, as well as whether any interrupts were missed"), **Tank swaps** (stacking debuffs: "which players are gaining stacks and when"), **Dispels** (timings) — https://www.archon.gg/classic-fresh/articles/news/wipefest-naxxramas , https://articles.classic.warcraftlogs.com/news/wipefest-ulduar (snippets). Neither "Ignited" nor an "engagement" metric could be found under those names on any public page; the role-specific content that *is* documented is the timeline's **healing cooldowns (major/minor), tank cooldowns and personal defensives, immunities and externals, debuffs, interrupts**, and the death popup with "time-to-death duration, total damage intake, healing received, and the last three damage events … indicating how much of each hit was overkill or absorbed" — original announcement https://www.mmo-champion.com/threads/2292937-Wipefest-a-new-web-tool-for-quickly-seeing-what-happened-in-a-fight! .
- **Scoring.** Raid mechanics score is relative to other guilds the same week ("A score of 75 means the raid performed better than 75% of other guilds that week"). Player score out of 100 = "how many points they earned with respect to the maximum number of points possible … weighted based on the relative importance of each mechanic" and "multiplied by the percentage of the fight that a player was alive for until their first death" (so a mid-fight death halves the score). Mechanics expand into who/when/how much. — https://hrothmar.com/guides/how-to-become-a-better-raider-using-wipefest-gg/ .
- **Pricing.** Free: single pull. **Rare $3/mo**: "report analysis … overviews of an entire raid night to easily see insights and deaths all at once" (and non-kill pulls per Hrothmar). **Legendary $10/mo**: "analyse up to 150 pulls from multiple reports, and share any analysis they generate with members of their guild" — https://www.patreon.com/wipefest . Per boss, not per spec.

### Archon (WCL's parent brand)
- Popularity-based **Builds and Tier Lists**: talents, gear, enchants, consumables "further broken down by encounter, difficulty, or key level", all specs, launched in beta 2023-12-14; raid filter by boss and difficulty; dungeons by Fortified/Tyrannical and key ≥ 20 at launch — https://www.wowhead.com/news/archon-feature-launch-popularity-based-tier-lists-and-character-builds-by-336729 . It is "popularity-based" (what top parses run), not sim-based, and by 2026 includes a cross-game companion overlay — https://wowcarry.com/blog/wow/warcraft-logs-feature-release-popularitybased-tier-lists-and-character-builds-by-archon . No per-player "your log vs top logs" report was found on accessible pages; that comparison is done in WCL itself (talent heat maps, Compare). Free.

### Raidbots
- **Top Gear** (try combinations of owned items/talents), **Droptimizer** (sim every drop of a raid/dungeon one piece at a time; output = item list with % DPS gain grouped by boss, Expected Value, Best Drop, Priority) — https://support.raidbots.com/article/59-droptimizer-how-does-it-work , https://www.raidbots.com/simbot/topgear . Premium unlocks full options (all dungeons at once etc.) — same support page. Presentation: horizontal bar per item, % upgrade, grouped by source.
- **Sim vs log**: no such feature exists in the Raidbots docs; community threads treat the sim as a Patchwerk ceiling with no fixed ratio to real DPS — https://www.mmo-champion.com/threads/1753844-Sim-DPS-vs-Real-DPS .
- Discord: official **Raidbots bot** (quick sims from Discord) — https://medium.com/raidbots/raidbots-discord-bot-5a342f19809b ; guild tooling aggregates Droptimizer reports for loot decisions — https://github.com/maxine4j/droptimizer .

### WoWAnalyzer (presentation side only)
- **Guide format** = "a way of presenting our existing analysis that is focused on details & readability" with `Section`s and a `ProblemList` "sorted in order of priority" — https://github.com/WoWAnalyzer/WoWAnalyzer/blob/master/src/interface/guide/index.tsx .
- **Four-level qualitative scale**: `Perfect / Good / Ok / Fail` ("the player did the mechanic … perfectly / correctly / suboptimally, but it's not a big deal / incorrectly"; explanations "Perfect usage / Good usage / Ok usage / Bad usage") — https://github.com/WoWAnalyzer/WoWAnalyzer/blob/master/src/parser/ui/QualitativePerformance.ts .
- **Components** (all in `src/interface/guide/components/`): `PerformanceBoxRow` ("A row of boxes colored based on performance", one box per cast, tooltip per box, click to inspect), `GradiatedPerformanceBar` (perfect/good/ok/bad counts as one stacked bar), `PassFailBar`, `CastEfficiencyPanel` (efficiency % + "minimal cast / CD timeline", colour-coded by threshold), `BuffUptimeBar`, `TimelineHeatmapGrid` (bracketed value over time, e.g. mana % ranges), `DamageTakenPointChart`, `MajorDefensives/*` (mitigation windows with `MitigationSegments`, `Timeline`, `DamageMitigationChart`), `Preparation/*` (enchants, gems, weapon enhancements, flask/food vs recommended lists), `CooldownGraphSubSection`, `HideGoodCastsToggle`, `HideExplanationsToggle`, `TipBox` — folder listing via GitHub API, e.g. https://github.com/WoWAnalyzer/WoWAnalyzer/tree/master/src/interface/guide/components .
- **Legacy Checklist/Suggestions**: checkmarks + progress bars; suggestions ranked Major/Average/Minor, minor hidden by default — https://www.peakofserenity.com/2019/10/04/analyzing-the-analyzer-the-basics/ ; abilities flagged "can be improved" when undercast — https://hrothmar.com/guides/how-to-improve-your-dps-with-wowanalyzer/ .
- Deep per-spec logic maintained by volunteers ("Spec support is inconsistent"); free/open source, $1/mo removes ads — https://wowcoach.gg/blog/warcraftlogs-vs-wowanalyzer-vs-wowcoach . Discord bot that replies to WCL links with a WoWAnalyzer link — https://github.com/WoWAnalyzer/DiscordBot .

### Other tools raiders use (Discord bots, sheets, newer sites)
- **Warcraft Insights** (free, Patreon-funded): reads *public* logs, hand-built per-boss mistake lists, "counts hits and deaths from avoidable mechanics while excluding wipe-phase deaths", repeated hits in a short window counted once; **per-player sortable mistakes-per-pull table "cleanest raiders first"**, recap awards (healthstones, attendance), "recruitment cards" with parse percentile + mechanical discipline + reliability — https://www.warcraftinsights.com/ . Directly comparable to this project's `avoidable.json`; also a cautionary example for public per-name ranking.
- **Mr. Mythical Raid Log Visualizer**: damage and healing on a shared second-by-second axis, toggle healer cooldowns to find coverage gaps, death hotspots in 5-second windows, per-second damage-taken averages with confidence bands from public Mythic kills — https://mrmythical.com/raid .
- **WowCoach.gg** (paid, $5.99-12.99/mo): death recaps "with available defensives", GCD gaps, healing flow, pull-by-pull trends, chat coaching — https://wowcoach.gg/blog/warcraftlogs-vs-wowanalyzer-vs-wowcoach .
- **Carried.io** (M+): six-axis "behavioral score" — interrupts, CC, avoidable damage, dispels, survival, activity — tagline "Does he kick or Netflix?" — https://www.carried.io/ (example of *tone to avoid*, see §5).
- Discord plumbing: auto-post new WCL reports via webhook — https://github.com/redfellow/WarcraftlogsDiscordWebhook ; NinjaBot latest-report command — https://www.gngrninja.com/ninjabot-command-reference/2017/6/8/world-of-warcraft-commands ; Wipefest and WoWAnalyzer link-reply bots (above). Spreadsheets in the wild are mostly attendance/loot (e.g. https://github.com/mendezm87/wow-raid-team-audit , https://lootdrama.com/ ), not per-player combat feedback.

## 2. Role metric catalogue

Column key — **Data**: WCL v2 table/events needed. **Spec**: none / list (a per-spec ability list) / deep. **Threshold**: community rules of thumb unless a tool's code is cited. **Form**: presentation that works in a static browser-rendered dashboard.

## 5. Anonymity and tone

**What the reference tools do.**
- Wipefest frames analysis as an *audit of mechanics* with a team score relative to other guilds and player scores that reward staying alive; the guide says "auditing is not a one-time process" and shows failures as expandable who/when lists rather than a leaderboard — https://hrothmar.com/guides/how-to-become-a-better-raider-using-wipefest-gg/ .
- WoWAnalyzer labels are neutral and about *usage*, not people ("Perfect usage / Good usage / Ok usage / Bad usage"); the scale explicitly allows "Ok — suboptimal, but it's not a big deal", and minor suggestions are hidden by default — https://github.com/WoWAnalyzer/WoWAnalyzer/blob/master/src/parser/ui/QualitativePerformance.ts , https://www.peakofserenity.com/2019/10/04/analyzing-the-analyzer-the-basics/ .
- WCL's Problems tab lists raid-level problems per pull with names only inside expandable sections; the parse colour scale is the part of WCL most often criticised: "a player who parses 60 while handling every mechanic is more valuable than someone who parses 90 while ignoring responsibilities" — https://wowcoach.gg/blog/what-your-wow-parse-score-means .
- Counter-examples: Warcraft Insights publishes public per-name tables "cleanest raiders first" and "recruitment cards" — https://www.warcraftinsights.com/ ; Carried.io markets "Does he kick or Netflix?" — https://www.carried.io/ . Both are exactly the surface a public guild Discord should not have.
- Raid-leadership advice: "Tone makes or breaks your debriefs"; mention individual mistakes only "if it's a learning point for everyone"; "Pick one fight. Pick one thing. Talk about it." — https://worldofmatticus.com/the-art-of-the-post-raid-debrief/ ; "praise in public, and criticize in private" — https://worldofmatticus.com/raid-leading-101-3-important-communication-tips/ ; codify expectations so metrics never "feel like a surprise", judge median not peak, hold officers to the same standard — https://raider.io/fr/news/556-raiding-101-performance-management ; serious issues "never … in front of the raid; always use DM with specific concrete data" — https://guildorder.com/games/wow/guides/raid-leadership .
- Platform norms: WCL lets players hide their parses from public view — https://us.forums.blizzard.com/en/wow/t/you-can-make-your-logs-private/1809815 ; guilds fight over members publishing "private" guild logs — https://forums.combatlogforums.com/t/individuals-publishing-guild-private-logs/6306 . A public dashboard that adds *judgement* on top of names is a step beyond what WCL itself exposes.

**Three concrete rules for the feature.**
1. **Public = team and self; named comparison only in the private build.** The Discord artefact shows per-player cards only behind the existing Player filter ("your view"), with the comparison expressed as *you vs your own history* and *you vs role median*; sorted per-name rankings, parse-coloured rosters and "worst N" lists exist only in the `--callouts named` raid-lead build (the project already has this switch).
2. **Positive, usage-centred wording with a "not a big deal" tier.** Every judgement uses a 3-4 level scale of *usage* (Good / Watch / Note, mirroring WoWAnalyzer's Perfect/Good/Ok/Fail), each card states the number, the baseline and one actionable sentence, good items are shown (and can be hidden) so the card is not a list of faults, and nothing is coloured red without text.
3. **Own history before peers, kills before wipes, one thing per night.** Default comparison order: this night vs the player's last 4 nights → role median in the roster → WCL bracket percentile (kills only) → external top-log aggregates (never named). Cap the public per-player card at ~3 "Watch" items per night, chosen by severity, and always include at least one "Good".
