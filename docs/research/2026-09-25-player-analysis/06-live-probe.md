## Findings (hand-written after the 2026-10-01 run; a re-run of the script overwrites this file)

- **Point cost is per subquery, not per byte.** Lag-corrected: a bare `report { code }` = 1, FIGHTS_QUERY = 2, PHASES_QUERY = 1,
  each `table(...)` = 1, `playerDetails(includeCombatantInfo)` = 2, one events page = 1 whether 7 KB or 2.3 MB (DamageTaken 10k
  page, whole-fight casts page), the 5-fight bundle (25 tables + 5 cinfo aliases) = 30, RANKINGS (dps + hps aliases) = 4,
  3 aliased `archiveStatus` reports = 1. An earlier identical run (same day, script then lost the counter because a concurrent
  `wcl_client.py` change strips `rateLimitData` from the returned data; the script now reads it from the raw HTTP body) showed the
  same pattern, with one 1.4-point table Casts. Consequence for Phase 2: **batching aliases saves HTTP requests, not points**;
  points scale with aliases + follow-up pages. Limit is 9000 points/hour, so a full rebuild (~700 requests) is far below it.
- **`pointsSpentThisHour` lags one request**: a response reports the total *before* its own charge. Per-request Δpoints logging in
  `wcl_client` (§6.2) must attribute each delta to the previous request (or compare against the next response).
- **Headers:** every 200 response carries `x-ratelimit-limit: 300` / `x-ratelimit-remaining` (a request-count limit separate from
  points; window not documented, likely per minute). No 429 occurred, so `Retry-After` on 429 is still unseen.
- **Summary table embeds `playerDetails`** (plus `composition`, `damageDone`, `damageTaken`, `deathEvents`, `itemLevel`, ...).
  `playerDetails` entries carry `minItemLevel`/`maxItemLevel`, `potionUse`, `healthstoneUse`, `specs[]` and a filled
  `combatantInfo` on this report (section 3).
- **`includeResources`** adds `resourceActor`, `classResources[{amount, max, type, cost}]` (mana = type 0), `hitPoints`,
  `maxHitPoints`, `attackPower`, `spellPower`, `armor`, `absorb`, `x`, `y`, `facing`, `mapID`, `versatility`, `avoidance`,
  `itemLevel` on 19 of 20 events (which row lacked them was not recorded; 8 of the 20 rows are `fake`). ~385 B per event.
- **Filtered queries do not paginate early here**: limit 100 returned exactly 100 events + `nextPageTimestamp`; the whole-fight
  casts page returned exactly 10,000 + a second page of 757. Pages fill to `limit`.
- **Whole-fight casts are ~2x the design estimate**: 0.96 events/s/player (not 0.72), 10,757 events for a 623 s Heroic kill;
  1,263 of them are `fake` (drop them, as P2.1 plans). ~104 B per event raw.
- **Interrupts table semantics (E9 / `ish`)**: for the listed spells `spellsBegun` = enemy `begincast` count and
  `spellsCompleted` = enemy `cast` count exactly (29/5 and 14/0). But the table lists **only spells that were interrupted at
  least once** (2 spells); 10 other enemy spells with `begincast` events are absent. So an interruptible spell nobody kicked in a
  pull is missing from the denominator -> E9 under-counts "interruptible casts" on bad pulls. Either accept that (wording:
  "of the kickable casts the raid engaged with") or derive the per-boss interruptible-spell list from tables across all pulls and
  count misses with the enemy-casts query (1 point, ~60 KB per pull).
- **`archiveStatus`** works as `{ isArchived isAccessible archiveDate }`; the fixture, the oldest cached report (2026-03) and
  the newest small Normal night are all accessible and not archived.

## Decisions

1. **FIGHTS+PHASES merge:** PHASES costs 1.0 vs FIGHTS 2.0 points (50 %) -> **merge recommended** (>= 50 %). Absolute saving at most 1.0 point(s) per report against a 9000 points/hour limit.
2. **Casts pages per whole-fight pull:** 2 page(s) ([10000, 757] events, 1117472 bytes) for the longest pull (623.0 s, 18 players, 17.3 events/s); at that rate a pull longer than about 579 s needs a second page. A 3-fight request of long pulls returns ~3 MB and truncates each alias at 10,000 events, so the P2.1 follow-up loop is required; 3 fights per request stays reasonable.
3. **archiveStatus:** fixture `3w1jJ8BZ2m9kMrYG` is **not archived** (`{"isArchived": false, "isAccessible": true, "archiveDate": null}`); keep it.
4. **Unknown specID:** **no unknown specID** appeared.
