## Data pipeline (`collect_data.py`, `cache.py`, `wcl_client.py`)
- `[FIXED]` `REPORT_META_QUERY` (used for `_include` / `--reports`) is no longer cached, so a live-logged included report is re-downloaded when it grows.
- `[CHANGED]` A changed report re-downloads only the fights whose absolute end time is newer than the previously seen `endTime`, plus the cheap report-level queries. Finished fights are immutable and stay cached.
- `[ADDED]` `wcl_client.run_query`: 60 s timeout (`WCL_TIMEOUT_SECONDS`), 4 attempts (`WCL_MAX_ATTEMPTS`) with backoff on 429 / 5xx / connection errors / GraphQL rate-limit messages, `Retry-After` honoured, 401 refreshes the token. Thread-safe token handling.
- `[ADDED]` Players are identified by (name, realm). `Labeller` gives the bare name unless the same name exists on two realms anywhere in the dataset, in which case both become `Name-Realm`. Deaths / damage / healing tables are matched by actor id, rankings by name + realm.
- `[ADDED]` `fight_percentage` (WCL `fightPercentage`: fight progress left, accounts for phases and council bosses) alongside `boss_percentage`. `[DECISION]` The grid and charts keep boss HP % because that is what raiders see on WCL's fight list; fight % is shown as an extra line in the pull box, in hover text and in the pull title when it differs by more than 1 point.
- `[ADDED]` `phase_timeline` per pull: `[[phase name, seconds], ...]` from the phase transitions WCL already returned.
- `[ADDED]` Per-fight **bundles**: DamageDone, Healing, Deaths, Interrupts, Dispels tables plus `CombatantInfo` events, fetched for 5 fights per HTTP request via GraphQL aliases, cached **per fight** (`cache.get_entry` / `put_entry`). If WCL rejects the extras the bundle falls back to damage/healing/deaths with one warning.
- `[ADDED]` `interrupts` / `dispels` per pull (`{player: count}`, nested table entries walked).
- `[ADDED]` `consumables` per pull: `{player: {flask, food, rune, prepot}}` from the auras active at pull start. Patterns in `consumables.json` (see `consumables.example.json`).
- `[ADDED]` Casts of the dying player in the `DEATH_WINDOW_SECONDS` before the **first death of each pull** (batched 10 pulls per request, cached per fight): `casts`, `defensives`, `has_cast_data`. Defensive names in `defensives.json` (see `defensives.example.json`) or the built-in list. `[DECISION]` First death only: that is the death the analysis is about, and it keeps the request count at one per ten pulls.
- `[ADDED]` Fights are fetched from a `ThreadPoolExecutor` (`WCL_PARALLEL`, default 4). Cache stats and writes are lock-protected; writes are atomic (temp file + replace).
- `[ADDED]` `DIFFICULTIES` in `.env` sets the default for `--difficulty`.
- `[FIXED]` `abilities_seen.json` is written next to the scripts, not into the current working directory.
- `[CHANGED]` `attach_recaps` indexes events per player first (was a full scan per death).
- `[ADDED]` `mplus.py --roster-from-raid ... --nights main|open`.

## Dashboard (`dash/` package, `build_dashboard.py`)
- `[CHANGED]` `build_dashboard.py` (2,583 lines) split into `dash/common.py`, `payload.py`, `home.py`, `raid.py`, `players.py`, `mplus_tab.py`, `page.py`, `static/dash.js`, `static/dash.css`; the CLI keeps its name and flags.
- `[REMOVED]` Every Python-rendered boss-tab section (progression chart, breaks, per-night, Summary, Damage/Healing done, Deaths, Damage taken, the unused `avoidable_table`). `[DECISION]` The browser is the only renderer for boss tabs, so the static and interactive views can no longer drift. Python still renders Home, Raid, Players (static), Mythic+ and the pull grid.

- `[ADDED]` Boss-tab sections now include: Phases (wipes by phase + **time to reach each phase** chart and table), Per raid night, Summary, **Preparation** (flask / food / rune / pre-pot at pull start per player), **Interrupts & dispels**, **Defensives cast** column in every death table, avoidable-hit timing histogram, ability table with *Cast by* / *Who gets hit* / ⚠ review flags, players table with Role + Hide tanks.
- `[ADDED]` Section navigation row inside each boss tab; deep links `dashboard.html#tab3` and `#tab3:deaths`.
- `[ADDED]` Home: progression trend uses the median of the three best pulls per night; "N of M pulls reached <deepest phase>"; "% of first deaths had no defensive cast"; "% of player-pulls started without flask or food". Avoidable review flags are labelled with the difficulty.
- `[ADDED]` Visible error banner (`#jsError`) with the message and stack if any script or chart fails; charts are drawn one by one so one bad chart cannot blank the rest.
- `[FIXED]` Bar charts without explicit colours crashed Plotly's `cleanData` (`marker: undefined`); keys are now only set when defined.

## Follow-up 4: potions and Healthstones were under-counted
- `[BUG]` `[FIXED]` **WCL's Casts table does not list item uses.** Ground truth for the longest Ula'tek pull (raw cast events): 16 Healthstones,
  12 health potions, 6 combat potions, 2 mana potions - the Casts table for the same fight: none. Potions/Healthstones now come from
  **filtered cast events** per fight (`events(dataType: Casts, filterExpression: "ability.id in (...)")`, ids = every ability in the
  report whose name matches a cast category), batched 10 fights per request, cached per fight (`cons:v1:<code>:<fid>:<ids-hash>`).
  The same events give the pre-pot (combat potion cast in the 5 s before the pull), so the bundle's `casts` table and `prepull`
  events were dropped (`BUNDLE_VERSION` **v3**).
- `[CHANGED]` Consumable categories: `combat_potion` (`potion` minus health/healing/mana), `healing_potion`, `mana_potion`,
  `healthstone` (casts) + `flask`, `food`, `vantus`, `rune` (auras). Patterns starting with `-` exclude. Pull field
  `consumable_use` {player: {category: n}}; payload `use` / `usecats`. Preparation section renamed "Preparation & consumables":
  per-category "/ pull" cards and per-player columns (with per-pull rate). An old-style `consumables.json` with `prepot` still loads.
- `[CAVEAT]` The whole range refetched its bundles (~70 calls). Verified after the rebuild: the Ula'tek fight-24 counts in the payload
  equal the raw-event counts.
