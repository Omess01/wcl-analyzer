- `[ADDED]` `docs/plans/2026-09-25-player-analysis-design.md`: design proposal and roadmap for the next phase, a per-player view
  of the dashboard (DPS / healer / tank / raid-lead) inspired by WoWAnalyzer and SimulationCraft. Contains a feature catalogue

  a Phase 0-4 roadmap (0 hygiene, 1 mine the cache, 2 casts + oracle, 3 role depth + RL, 4 SimC opt-in) with acceptance criteria,
  effort and `model` per task; and ten decisions Q1–Q10 for the user (§9). Nothing in it is implemented; no code changed.
- `[ADDED]` `docs/research/2026-09-25-player-analysis/`: the six research inputs behind the design (persisted copies of the
  session scratchpad, each with a one-line provenance header):

  - `01-codebase-inventory.md` — per-player data the code already has, verbatim queries, batching, cache keys and sizes,
    payload budget, Players tab today, config conventions, extension points with `file:line`, fixture mechanics.
  - `02-wowanalyzer.md` — WoWAnalyzer architecture, spec-agnostic modules with thresholds, normalizer pitfalls, guide UI,
    spell-data sources, AGPL implications, support matrix, feasibility of a Python port.
  - `03-simulationcraft.md` — SimC state, Linux build / Docker, WCL→SimC profile mapping, `json2` fields for baselines,
    `SpellDataDump` as an offline oracle, APL comparison judged infeasible, integration options ranked.
  - `04-wcl-api.md` — `events` / `table` / `playerDetails` / `rankings` capabilities, event shapes from the cache, measured
    volumes per pull, rate limits, pitfalls, cheap / moderate / expensive classification, "verify with one live call" list.
  - `05-insight-catalogue.md` — competitive landscape (WCL, Wipefest, Archon, Raidbots, WoWAnalyzer, ...), per-role metric
    catalogue with thresholds, baselines without spec knowledge, presentation patterns, tone rules, prioritised shortlist.
- `[DECISION]` Research and design were produced by sub-agents per `CLAUDE.md` §0: five parallel research agents (`01`-`05`),
  one synthesis agent (the design document), one review agent and one docs agent (this entry); the orchestrator wrote only
  the brief (`00-brief.md`).
- `[CAVEAT]` Two code pitfalls were found during research; they are scheduled as Phase 0 fixes and are **not fixed yet**:
  - the "externals received" list before the first death can include buffs the dying player cast on others:
    `events(dataType: Buffs, targetID: X)` also returns buffs where X is the source, and `attach_casts()` only drops
    `sourceID == targetID` (see `docs/research/2026-09-25-player-analysis/04-wcl-api.md` §1);
  - the aliased per-fight event queries (`cinfo`, `cons`, `casts`, `buffs`) request only `{ data }` and never
    `nextPageTimestamp`, so a truncated page would go unnoticed.
