### Fetcher hygiene (P0.1–P0.3) — `collect_data.py`

- `[FIXED]` **Buffs `targetID` leak** in `attach_casts()`: the first-death Buffs query (`targetID:`) also returned buffs the dying actor cast on
  others (e.g. a dying healer's Pain Suppression on a tank showed up as an external they received). A buff is now kept only if
  `targetID == death["actor_id"]`; self-buffs are still skipped. The fix runs at read time, so it corrects already-cached entries too.
- `[FIXED]` **`nextPageTimestamp` pagination**: the aliased `events(...)` fetchers ignored the cursor and silently truncated at their `limit`.
  New `_follow_pages(...)` follows `nextPageTimestamp` with single-alias follow-up queries (same variables), `count_api_call(1)` per follow-up,
  concatenates `data`, prints `  (page 2+ needed for <code>:<fid> <kind>)` once per fight/kind and stops if the cursor does not advance.
  Applied to the bundle `cinfo` alias (new `_cinfo_part()`, `_bundle_query()`, `_fetch_bundle_batch()`), `get_consumable_casts()` and
  `get_first_death_casts()` (casts and buffs). `get_pull_events()` is deliberately untouched (earliest events only).
- `[CHANGED]` **Consumables `filterExpression` as a GraphQL variable**: `ConsumableCasts($code: String!, $filter: String)` with
  `filterExpression: $filter`, variables `{"code", "filter"}`; no more string interpolation into the query text.
- `[DECISION]` **No cache-key change / no version bump**: `_bundle_key`, `_cons_key`, `_casts_key` are built from version/code/fight id/ids/window,
  never query text. `[CAVEAT]` cached entries fetched before the fix may still be truncated if they hit the limit; only `--refresh` (or a version
  bump) re-fetches them. Follow-up failures sit inside the existing `WCLError` handler, so a partial result is never cached.
- `[ADDED]` Tests: buff targetID filter (synthetic + fixture entry, Earth Shield 4 → 13), pagination for consumables / first-death buffs / bundle
  cinfo (2 `run_query` calls, API counter +2), filter-as-variable with unchanged `_cons_key`.

### Rate-limit visibility and clean stop (P0.4) — `wcl_client.py`, `collect_data.py`, `build_dashboard.py`

- `[ADDED]` `run_query` appends ` rateLimitData { limitPerHour pointsSpentThisHour pointsResetIn }` inside the outermost braces **at send time only**
  (`_with_rate_fields`); the caller's query text is untouched, so `cache._cache_path` (sha1 of caller text + variables) and every existing cache
  key are unchanged. `rateLimitData` is popped from `payload["data"]` before returning, so cached files and fixtures keep their shape. The value is
  kept in the lock-guarded `wcl_client.last_rate`.
- `[ADDED]` One console line per request: `  [wcl] <op> <spent>/<limit> pts this hour, reset in <s> s`, plus `; <previous op> cost N pts` when
  both requests ran with nothing else in flight. `[CAVEAT]` WCL reports `pointsSpentThisHour` **one response late** (a response shows the total
  before its own charge), so the cost is attributed to the previous request; overlapping requests (`WCL_PARALLEL` > 1, bundle fetches) only show
  the running total.
- `[ADDED]` `rate_summary()` → `WCL points this run: X of Y per hour (...); resets in Z s` (+ the last request's cost, reported one response late;
  `requests: R of L remaining (x-ratelimit window)`), printed by `collect()` after `cache.summary()`.
- `[ADDED]` `x-ratelimit-limit` / `x-ratelimit-remaining` request-count headers of every 200 response are stored in `last_rate["req_limit"]` /
  `["req_remaining"]`; one warning when remaining < 10 % (`REQ_BUDGET_WARN_FRACTION`). Retry-After / X-RateLimit-* headers of a 429 are printed once.
- `[ADDED]` **Wait-or-stop**: on HTTP 429 or a GraphQL "rate limit" error the existing short backoff runs first; then, only if spent ≥ 95 % of the
  hourly limit, sleep `pointsResetIn` and retry once when it is ≤ `WCL_RATE_WAIT_MAX` (seconds, default 900), else raise `WCLRateLimited`.
  A second rate limit after the long wait also raises. Below 95 % behaviour is unchanged.
- `[DECISION]` `WCLRateLimited(RuntimeError)` is deliberately **not** a `WCLError`, so the degrade-silently fetchers (`except WCLError`) let it
  through; `collect_data.py` re-raises it before its bare `except Exception` blocks. Finished reports stay cached (per-report `save_meta`).
- `[ADDED]` `build_dashboard.main()`: `WCLRateLimited` → `stopped: hourly points exhausted, resets in N s; finished fights are cached, re-run later`
  and **exit code 3**. `--refresh` first issues one minimal `query RateLimit { rateLimitData {...} }` (bypasses the cache) and refuses with exit 3
  when more than 80 % is spent (`RATE_REFRESH_MAX_FRACTION`).
- `[CAVEAT]` `WCL_RATE_WAIT_MAX` is a new optional `.env` key; Claude Code cannot edit `.env` / `.env.example`, so the user adds it by hand if a
  different ceiling is wanted.
- `[CAVEAT]` The long wait sleeps exactly `pointsResetIn` with no margin; if WCL rounds down, the run stops with `still rate limited after waiting`.
  `[FIXED]` later today: 5 s margin and elapsed-time correction (see "Review follow-ups" below).
- `[ADDED]` `tests/test_wcl_client.py` (13 offline tests: fake session/token/sleep).

### Live probe (P0.7) — `tools/wcl_probe.py` (new), `docs/research/2026-09-25-player-analysis/06-live-probe.md` (new)

- `[ADDED]` `tools/wcl_probe.py` calls `wcl_client.run_query` directly (never the cache, never writes `data/cache`), reads `rateLimitData` from the raw
  body, redacts player names to P1..Pn (refuses to write on a leak), stops on the second 429.
- Findings (details and raw snippets in `06-live-probe.md`):
  - Cost is **~1 point per alias / subquery / page, independent of bytes** (a 5-fight bundle = 30 points); batching saves HTTP requests, not points.
  - Hourly limit **9000 points**; `pointsSpentThisHour` **lags one request**.
  - Every response carries `x-ratelimit-limit` / `x-ratelimit-remaining` (request-count limit observed 300 (probe) and 800 (build); window
    length unknown); no 429 seen.
  - Whole-fight casts for a 623 s pull = **2 pages** (10,000 + 757 events; ≈ 0.96 events/s/player).
  - Fixture report and the probed reports are **not archived**; **no unknown specID**.
  - Interrupts table lists only spells interrupted at least once, so never-kicked interruptible spells are missing from the E9 denominator.
- `[DECISION]` **FIGHTS+PHASES merge skipped**: it meets the design's ≥ 50 % rule (PHASES 1 vs FIGHTS 2 points) but saves only 1 point per report.
- `[CAVEAT]` Re-running the probe overwrites `06-live-probe.md`, including its hand-written Findings section.
