## Who pulled

**Request (user, 2026-09-29):** "I want to see who and how many times someone pulls first on every boss and in total."
Plan: `docs/plans/2026-09-29-who-pulled.md` (Tasks A collector, B dashboard, C docs, D verification; one sub-agent each per `CLAUDE.md` §0).

### Rule

- `[ADDED]` `collect_data.pull_initiator()` credits a pull to the participant behind the **earliest qualifying friendly event** with a timestamp
  in `[fight.startTime - PULL_TOLERANCE_MS, fight.startTime + PULL_WINDOW_MS]` (1 000 / 5 000 ms):
  - `damage`: event type `damage` whose `targetID` is in the fight's enemy set;
  - `cast`: event type `cast` (never `begincast`) on an enemy **and** either the same `abilityGameID` also appears in a qualifying damage event in
    the window, or the ability name is in `PULL_TAUNTS` (taunt, growl, dark command, death grip, hand of reckoning, provoke, torment, challenging shout).
  - The source must be a participant; pets resolve to their owner (`via_pet: true`). Ties at the same millisecond: damage before cast, then log order.
    No qualifying event → `None` (shown as "Unknown").
- `[DECISION]` The damage-or-taunt condition on casts: WCL records self-buffs with the caster's current target (e.g. Ascendance → boss at +39 ms),
  so "cast on the boss" alone is not an attack; a tank's Dark Command has no damage event, hence the taunt list.
- `[DECISION]` Casts on friendly targets (shields, misdirection) and on WCL's targetless "Environment" actor (id -1) never count.
- `[CAVEAT]` A body pull (nobody acts, the boss aggroes) is credited to the first player who then hits it — documented, not solved (plan §5).

### Collector (`collect_data.py`)

- `[ADDED]` New key on **every** pull: `"pulled_by": {"player", "class", "ability", "offset_ms" (int, relative to fight start), "kind": "damage"|"cast", "via_pet": bool}` or `None`.
- `[ADDED]` `PULL_ACTORS_QUERY` (report level, cached through `cq()`): `fights { id enemyNPCs { id } friendlyPets { id petOwner } }` +
  `masterData { actors(type: "Pet") { id petOwner } }`, read by `get_pull_actors()`. `enemyNPCs` excludes the Environment actor. Per-fight
  `friendlyPets` is authoritative (`masterData.petOwner` is empty for guardians such as Ancestor / Hati). Kept separate from `FIGHTS_QUERY` so the
  cached fight lists stay valid. Fallback when the query fails or the list is empty: every NPC id ≥ 0 from `npc_names`.
- `[ADDED]` `get_pull_events()`: per fight `pbd_<fid>: events(dataType: DamageDone, hostilityType: Friendlies, fightIDs, startTime: start-1000,
  endTime: min(start+5000, end), limit: 1000)` and `pbc_<fid>: events(dataType: Casts, ..., limit: 500)`, 10 fights per request (`CASTS_BATCH`),
  cached per fight under `entry:puller:v1:<code>:<fid>` (`_puller_key()` passes `puller:v1:...`, `cache.py` adds `entry:`), refreshed through
  `needs_refresh(f)`, `count_api_call()` per request; `WCLError` → `_warn_once` and the batch's pullers become unknown. Runs on the existing
  pool right after `get_fight_bundles()`.
- `[ADDED]` Constants `PULLER_VERSION` ("v1"), `PULL_TOLERANCE_MS`, `PULL_WINDOW_MS`, `PULL_DAMAGE_LIMIT`, `PULL_CAST_LIMIT`, `PULL_TAUNTS`.
- `[CHANGED]` Console: the per-fight line (new / changed reports only) now ends with `, pulled by <name> (<ability>, +0.05 s)` or `, puller unknown`.

### Real-data findings

- `[CAVEAT]` **WCL exposes no events before a fight's startTime** (verified with and without `fightIDs`). `PULL_TOLERANCE_MS` therefore only guards
  synthetic input. Unrelated but important: the existing pre-pot detection (`PREPOT_BEFORE_MS` = 5000) can only see potions pressed *after* fight
  start (up to `PREPOT_AFTER_MS` = 1.5 s), so the Preparation "prepot" flag under-reports.
- `[CAVEAT]` **Ula'tek starts on its own** (proximity / RP): in 3 of 19 prog pulls the first friendly attack came 372–453 ms after fight start; the
  credited player is then the *first attacker*, not a true puller. Offsets ≥ ~300 ms are the tell; the pull table shows the offset.
- Two real nights (30 pulls): 30 / 30 attributed, 23 by damage / 7 by cast, 1 via pet; offset median 34 ms, max 453 ms.
