## 1. Correctness bugs in the pipeline

1. `[CAVEAT]` **`_include` / `--reports` reports never re-download while live.** `fetch_reports_by_code()` uses `cached_query(REPORT_META_QUERY)`, so the endTime it returns is frozen at first fetch. Change detection compares stale-vs-stale and says "unchanged"; fights logged after the first fetch are never seen. `[TODO]` call `run_query` (uncached) for `REPORT_META_QUERY`, matching the "report list is never cached" rule.
2. `[CAVEAT]` **A changed report re-downloads *every* query for it,** including fights that ended long before the previous endTime (finished fights are immutable). For a live log with 25 pulls that is ~150 extra API calls per run. `[TODO]` refresh only fights whose `endTime > seen_end` plus the report-level queries (fights/abilities/actors).
3. `[CAVEAT]` **No timeout, retry or 429 handling in `wcl_client.run_query`.** A single network blip aborts a 10-minute first build; WCL rate-limit responses surface as a stack trace. `[TODO]` `timeout=60`, 3 retries with backoff on 429/5xx/connection errors.
4. `[CAVEAT]` **Players are keyed by character name only.** WCL actors carry `server`; two same-named characters on different realms (common in cross-realm guilds and on open nights with pugs) merge into one row in every table. `[TODO]` request `server` in `FIGHTS_QUERY` and key on `Name-Realm` internally, display the name only.
5. `[CAVEAT]` `abilities_seen.json` is written to the **current working directory** (`open("abilities_seen.json")`) while every other file uses the script directory. Running from elsewhere scatters files. `[TODO]` use `os.path.join(HERE, ...)`.
6. `[CAVEAT]` **`bossPercentage` is the wrong number for multi-boss / multi-phase encounters.** WCL's own pull grid uses `fightPercentage` (progress through the whole fight incl. phases and council bosses). On Twin Fangs, Entombed Sentinels, Lost Explorers and phased Ula'tek the "35.4%" shown can differ from what raiders see on WCL. `[TODO]` fetch both, show `fightPercentage` in the grid/chart, keep `bossPercentage` in hover.

## 2. The dashboard file: size and duplication

- `[CAVEAT]` **8.3 MB and growing ~2 MB per month.** Discord's attachment cap for accounts without Nitro is 10 MB, so the next tier-month build will not upload. Breakdown of the current file:

  | part | bytes |
  |---|---|
  | embedded per-boss JSON (`data_tabN`) | 4.46 MB |
  | 172 static Plotly chart `<script>` blocks | 1.64 MB |
  | dashboard JS (`DASH_JS`) | 44 KB |
  | CSS | 10 KB |
  | tables etc. (476 tables, 7,909 rows) | ~2.1 MB |

- `[DECISION]` **Every boss tab is rendered twice: once in Python (static) and once in JS (`renderSelection`).** The two have already drifted: the static ability table has *Cast by*, *Who gets hit* and ⚠ review flags, the dynamic one does not; the static damage-taken players table has *Role* + *Hide tanks*, the dynamic one does not; the static tab has the per-night table, the dynamic one does not. Recommendation: make the browser the **only** renderer for boss tabs (call `renderSelection` with "all pulls" on tab open). This deletes ~900 lines of Python HTML code, removes the 1.6 MB of static charts and ~1.5 MB of static tables, and ends the drift. Python keeps: data collection, Home, Raid, Players-static, Mythic+.
- `[TODO]` **Shrink the JSON payload** (independent of the above, ~4–8× gain):
  - dictionary-encode player and ability names (`names: [...]`, rows reference indices) — the `dt` rows repeat the same strings hundreds of times per pull;
  - or embed the payload gzip+base64 and inflate with `DecompressionStream('gzip')` (Chrome 80+, Firefox 113+, Safari 16.4+); expect ~600 KB instead of 4.5 MB.
- `[TODO]` Plotly is loaded from the CDN (fine) but the file still cannot be viewed offline; if hosting is ever considered (GitHub Pages / Cloudflare Pages behind a private URL), the size ceiling disappears and the Discord post becomes a link.
