## 1. Bugs

1. `[BUG]` **Interrupts and dispels are always 0.** WCL nests these tables as `entries[] (ability) → details[] (player, id, total)`; the
   walker in `counts_from_table()` only descends `entries`, never `details`. Probe: Counterspell / Detox / Cleanse present in cached
   bundles, payload totals 0. Fix: also walk `e.get("details")`. No refetch needed (data is cached).
2. `[BUG]` **"Augment rune" column is wrong.** The pattern `"augmentation"` matches the Evoker buffs *Draconic Augmentation* /
   *Ethereal Augmentation* (5% of player-pulls, all Evoker targets); no actual rune aura appears in any pull-start snapshot. Fix: drop
   `"augmentation"`, keep `"augment rune"`, and add a **Vantus rune** category (`"vantus rune"` — present in the data: *Vantus Rune: Ula'tek*).
3. `[BUG]` **Pre-pot is 0% across 4,902 player-pulls**, which is not credible on a progression raid. The combatant-info aura snapshot
   evidently does not carry short potion auras (or the names lack "Potion"). Fix: detect pre-pots from `Casts` events in the window
   [pull −3 s, pull +2 s] for all players — one extra alias in the fight bundle (`BUNDLE_VERSION` → v2, ~50 API calls to refill).
   Until fixed, hide the column rather than show a false 0%.
4. `[BUG]` **"Show hidden players" toggles only the first role table** in Damage done / Healing done (`nextTable()` stops at the first
   `<table>` after the label; Tanks and Healers tables keep their low-participation rows hidden). Fix: toggle every `table` inside the
   enclosing section, or emit one label per table.
5. `[CAVEAT]` **"No defensive cast" overstates.** Only the dying player's own casts are fetched; externals received (Pain Suppression,
   Life Cocoon, Blessing of Sacrifice...) are invisible. 27 of 202 first deaths show a defensive; the true number is higher. Fix: add a
   `Buffs` events alias for the dying player in the same death window (batched like the casts) and list "received: …" separately.
6. `[CAVEAT]` **Title keyword beats weekday.** A main-night log titled with the word "open" (e.g. "reopening", "open the cage") is
   classified open before the Thu/Sun rule runs. Low risk; consider matching whole words or moving the keyword rule after the weekday rule.
7. `[CAVEAT]` **Mythic+ callout right after reset** always reads "0 of 24 have done 4 x +10 this week" on Wednesday/Thursday builds.
   Suppress it for the first ~48 h of a reset week, or phrase it as "week just started".
8. `[CAVEAT]` **Interrupt attribution needs a check after fix 1**: WCL's `details[].actors` lists the *interrupted* casters; the player is
   the `details[]` entry itself. Verify one pull by hand against WCL after implementing.

## 2. Visualization (ui-ux-pro-max rules applied)

Style profile match: *Data-Dense Dashboard* (dark supported; requires 4.5:1 text, keyboard, visible focus, reduced motion — all now
met). Findings, most impactful first:

- `[TODO]` **Navigation overload.** 18 boss tabs wrap into four rows (Normal + Heroic). Rule: overloaded nav is an anti-pattern. Options:
  a difficulty segment (Normal | Heroic | Mythic) above a single row of boss tabs; or collapse Normal into one "Normal" tab with a
  boss switcher inside; on ≤700 px replace the tab bar with a `<select>`.
- `[TODO]` **Series distinguished by hue only** (progression chart per night, time-to-phase per phase, first-kill timeline per difficulty).
  Chart rule: add dash styles / marker symbols and direct labels; never hue alone. Plotly: `line.dash` cycling `solid/dash/dot`, distinct
  `marker.symbol`.
- `[TODO]` **Heatmap without values.** Rule: print values or symbols in cells and give the colour scale a numeric legend title. Plotly:
  `texttemplate:'%{z}'`, `colorbar.title:'hits / pull'`. Same for the Mythic+ heatmap.
- `[TODO]` **Reserve chart space.** `.chart` divs are empty until Plotly draws → layout shift while reading. Set `min-height` from the
  requested height (`style='min-height:380px'`) — trivial in `chart()`.
- `[TODO]` **Colour-only severity on "Worth a look" cards** (left border red/green/blue). Add a text badge ("warning" / "good" / "note")
  and an SVG glyph; same for `tag warn/good`.
- `[TODO]` **KPI cards lack context.** Six numbers with no target or delta. Add a small delta line vs the previous night / week
  (pulls/hour ↑, idle % ↓, median time-to-first-death →) as text with an arrow glyph, or a compact bullet bar where a target exists
  (idle < 30 %, flask/food 100 %).
- `[TODO]` **Time-to-phase is the best prog signal but sits third.** Promote it: on a prog boss show "phase reached per night" as a small
  KPI strip at the top of the tab (P2 in 41/49 pulls, P3 in 8/49, best 6:48).
- `[TODO]` **Pull grid density.** 10 columns × 5 lines of 12 px text is a lot; consider a compact mode (%, #, duration) with details on
  hover/focus, and a colour scale legend for the % text (red→green) since colour also encodes progress.
- `[TODO]` **Two sticky bars** (toolbar + section nav) eat 100 px on laptops; make the section nav non-sticky below 900 px or merge it into
  the toolbar row when a boss tab is active.
- `[TODO]` **Typography**: consider a monospace numeral font (Fira Code/JetBrains Mono, `font-variant-numeric: tabular-nums`) for
  tables so columns of numbers align; keep body sans.
- `[TODO]` **Home hierarchy**: the progress strip and the first-kill table now say similar things; keep the strip as the visual and move
  the table under a `<details>` or into the Raid tab to shorten Home.
- `[TODO]` **Mobile tables** scroll horizontally (correct per rule) but lose the player column; make the first column sticky
  (`position: sticky; left: 0`).

## 3. Data the raid lead would use (prioritised by value ÷ cost)

1. **Externals received before death** (see bug 5) — completes "did they try to survive?".
2. **Pre-pot + combat potions per pull** (fix 3; `Casts` table per fight gives potion counts) — the classic prep check.
3. **Raid cooldown timeline vs damage**: casts of raid/healer CDs (Rallying Cry, Darkness, Aura Mastery, Revival, Spirit Link…) per
   pull placed on the phase timeline, against damage taken per 5 s bucket. Shows whether CDs land on the spikes. One `Casts` events
   query per fight filtered to a CD list; render as a swim-lane chart under Progression for a single pull.
4. **Bench and late arrivals**: actors present in the report but not in any pull that night (sat out), and each player's first pull
   index per night ("arrived at pull 6"). Free — already in `masterData.actors` vs `friendlyPlayers`.
5. **Wipe anatomy**: time from first death to the death cascade (median gap first→second death, deaths in the 10 s after the first).
   Separates "one mistake wiped us" from "we bled out". All data present in `deaths`.
6. **Deaths by phase** (not just by second): bucket first deaths by the phase active at that time using `phase_timeline`. Answers
   "which phase kills us" better than the end-phase count.
7. **Per-player DPS trend on the prog boss** across nights (sparkline per row) — is the raid getting better or just luckier.
8. **Damage taken per phase** — extend `times` in the payload to all abilities (or bucket per phase server-side) so the heatmap can be
   filtered "Stage Two only".
9. **Consumables summary on Home** once fixes 2–3 land (flask/food/vantus/pre-pot % for the last night, per night type).
10. **Interrupt assignments** (after fix 1): expected vs actual per player when an `interrupts.json` assignment file exists.
